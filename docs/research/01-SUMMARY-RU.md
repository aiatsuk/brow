# brow — сводка исследования для владельца

**2026-08-04** · семь досье, ~5 700 строк, всё проверено на живом **Google Chrome 151.0.7922.72** через реальный `--remote-debugging-pipe` на macOS Darwin 25.5.0. Полный индекс, ADR, реестр рисков и план вех — в `00-README.md`. Здесь только то, что **меняет решения**.

---

## Вердикт

**brow строится как задумано — с четырьмя поправками к спеке.** Ни одна не фатальна, но каждая меняет границу crate'а или публичное обещание, поэтому решать надо до кода.

1. **«Persistent Chromium» + «рестартуемый daemon» + «без TCP-порта» требуют четвёртого процесса.** Измерено: Chrome выходит с `rc=0` через **0.053 с** после EOF на fd 3. Кто держит pipe — тот владеет жизнью браузера. Нужен per-browser `brow-supervisor`, отделённый `setsid()`, который держит fd 3/4 и переэкспортирует протокол в unix socket `0600`. На macOS выживание подтверждено экспериментально (реальный LaunchAgent + `launchctl bootout`: setsid-внук жив, контрольный процесс той же pgid мёртв; `man 5 launchd.plist` говорит, что reaping идёт по PGID). **На Linux `setsid()` не спасает** — `systemd.kill(5)` по умолчанию `KillMode=control-group`, process groups к cgroup отношения не имеют; нужен `systemd-run --user --scope --unit=brow-sup-<id>`.
2. **«ONE node model» — это структура данных в daemon, а не вызов CDP.** `DOMSnapshot.captureSnapshot` не возвращает ничего для cross-origin iframe; `DOM.getDocument{pierce:true}` отдаёт узел `<iframe>` с `frameId`, но без `contentDocument`; `Accessibility.getFullAXTree` **не пересекает вообще ни один iframe**, даже same-origin. Цена — O(frames) round-trip'ов и инвариант сшивки, который должен быть покрыт тестом, а не соглашением.
3. **«Raw CDP никогда не доходит до агента» выживает, но `inspect.evaluate` в isolated world не может извлекать роуты фреймворков.** Проверено дважды, на фикстурах и на пяти живых продакшн-сайтах: `Object.keys(node)` в isolated world **пуст**, `__reactRouterManifest` / `__vue_app__` / `__reactFiber$*` там `undefined`, при идентичном количестве DOM-узлов (reactrouter 118/118, nuxt.com 1945/1945, nextjs.org 2378/2378). Blink даёт каждому миру свой V8-wrapper. Значит нужен **третий уровень evaluate**: `inspect.routes` — фиксированные строки, написанные нами, в **main world**, помеченные как page-observable и page-tamperable. Агент по-прежнему не поставляет код.
4. **Crawler надо продавать как best-effort read-only, а не как containment.** Блокировка не-идемпотентных методов через `Fetch.requestPaused` (в исходном исследовании — «единственный надёжный слой») измеримо дырявая: `fetch()` изнутри service worker не даёт **ни одного** события паузы на page-session (POST дошёл до сервера, 200), мутирующие GET проходят по построению, WebSocket-handshake невидим, `localStorage.clear()` и `indexedDB.deleteDatabase()` не перехватываются. Фикс (auto-attach + `Fetch.enable` на каждой сессии `service_worker`/`worker`) проверен и закрывает главную дыру, но слой всё равно не sound.

Две правды, которые не меняют архитектуру, но обязаны изменить формулировки:

- **Каждая страница видит `navigator.webdriver === true`.** Полная матрица из 8 строк: без CDP — `false`; websocket — `false`; websocket + `--enable-automation` — `true`; **pipe — `true` и в headless, и в headful**; pipe + `--disable-blink-features=AutomationControlled` — `false`. То есть это делает наш транспорт, а не флаг автоматизации. Отключить честно нельзя.
- **Coverage считается только против *declared* роутов, с provenance по источникам.** Покрытие параметризованных роутов не «сложное», а бессодержательное. Инстинкт спеки («сообщать coverage и provenance вместо вида исчерпывающего обхода») исследование подтверждает цифрами.

## Что подтвердилось (и на что можно опираться)

- **Транспорт.** Формат провода прочитан из `devtools_pipe_handler.cc` и проверен живьём: fd 3 — Chrome читает, fd 4 — пишет, NUL-терминированный UTF-8 JSON, без префикса длины. Стартап до первого `Browser.getVersion` — 0.19 с headless / 0.27 с headful. Никакого HTTP-эндпоинта, никакого `DevToolsActivePort`.
- **Flat protocol.** Один глобальный `AtomicU64` для `id` безопасен: два одновременных `id:99` на разных сессиях вернулись корректно и различались только по эхо `sessionId`. Писать в pipe должна **одна** задача — иначе поток портится.
- **BrowserContext.** Полная изоляция cookies/localStorage/permissions подтверждена; пустой контекст почти бесплатен, живая страница стоит ~149 МБ независимо от контекста, отдельный `--user-data-dir` браузер — ~505 МБ и 6 процессов. **Но контексты не персистятся на диск** — долгоживущий логин возможен только в именованном профиле.
- **Closed shadow DOM виден CDP и невиден JS.** `DOM.getDocument{pierce:true}`, `DOMSnapshot` и `getFullAXTree` — все трое проходят сквозь closed roots; из isolated world `shadowRoot === null`. Это сильнейший аргумент за CDP-native дерево против JS-обхода. Разница между API — не видимость, а **provenance**: только `getDocument{pierce}` говорит, что узел живёт в closed root.
- **`DOMDebugger.getEventListeners{objectId:<document>, depth:-1, pierce:true}` отдаёт карту слушателей всей страницы за один вызов**, включая closed shadow roots и same-origin iframes. Предположение брифа, что это дорого и по-узловое, неверно. Зато `isClickable` из DOMSnapshot лжёт в обе стороны: пометил `#document` (из-за одного делегированного root-хендлера) и пропустил три обычных `<button>`.
- **Input.** Все синтезированные события `isTrusted:true` — единственное исключение — `compositionend` из `insertText`. `Input.dispatchTouchEvent` работает **без** touch emulation (эмуляция нужна для feature detection, а не для доставки). `synthesizeScrollGesture` блокирует до затухания fling'а (два независимых прогона: 1.353 с / scrollTop 733 и 1.292 с / 730), `speed` — px/s, `preventFling` по умолчанию `true`. `insertText` уважает `maxlength` и стреляет `beforeinput`/`input` — React-safe.
- **Capture.** `position:fixed` **не дублируется** в full-page снимке — рендерится ровно один раз на `y == scrollY` (воспроизведено на двух независимых фикстурах). Потолка в 16384 px нет: сняты 756×100000 headless и 1600×200000 headful. `screencastFrame.metadata.timestamp` — это wall-clock epoch секунды, расхождение с часами хоста 1.5 мс, то есть синхронизация видео с логом действий почти бесплатна.
- **Read-only evaluate реален.** `Runtime.evaluate{throwOnSideEffect:true}` — fail-closed allowlist V8: все 12 прицельных обходов (`Reflect.set`, `Function()`, `eval`, `setTimeout`, `Promise.then`, динамический `import()`, callback в `String.replace`, подмена `toString`, Proxy get-trap, `structuredClone`, `forEach(e=>e.remove())`, мутация массива) бросили `EvalError: Possible side-effect in debug-evaluate`, накладные ~0.05 мс на вызов.
- **Prior art.** Цитаты из Crawljax (TWEB) и документации Burp Scanner проверены дословно; ключевая — «The crawler never *jumps* to a pending link… it either navigates directly from its current location, or reverts to the start location and navigates from there». Статья arXiv 2606.16650 существует, авторы и Table 5 (Judge 54.18%, PDiff 39.39%) подтверждены.

## Что оказалось невозможным или существенно ограниченным

Каждый пункт обязан попасть в `SKILL.md`. Агент, который верит в несуществующую возможность и молча получает пустоту, хуже агента, которому сказали «нет».

- **Canvas / WebGL / Flutter Web без semantics** — только пиксели. Домена `Canvas` в Chrome 151 нет, лога draw-call'ов нет, retained scene graph нет.
- **Скриншот отдельного OOPIF** — `Page.captureScreenshot` на не-top-level сессии отклоняется (`-32000`). «Per-frame» на деле означает «область top-level страницы, где живёт этот фрейм», вместе со всем, что родитель поверх неё рисует.
- **Корректный full-page на любом сайте** — lazy/IntersectionObserver-контент остаётся **пустым**; `captureBeyondViewport` его не подгружает. Помогает только scroll-priming, а он мутирует состояние страницы и стреляет аналитикой.
- **Авто-инвалидация рефов на навигации** — CDP этого не делает. После same-process навигации `describeNode`, `getBoxModel` и `scrollIntoViewIfNeeded` **успешно** отвечают по мёртвому документу и возвращают байт-в-байт старую геометрию. Ошибается только `resolveNode` (`-32000`, матчить по **коду**, не по тексту). Это самый опасный корректностный риск во всём корпусе.
- **Подключение к уже запущенному Chrome пользователя** — Chrome ≥136 игнорирует оба remote-debugging-ключа против дефолтной data dir. *(Утверждение «ключ шифрования привязан к каталогу данных» на macOS **не подтверждается** — там один общий Keychain-item; App-Bound Encryption только Windows. В `SKILL.md` этого писать нельзя.)*
- **Переподключение к pipe-браузеру, который мы не запускали** — невозможно. Один клиент, никакого discovery. Только наш собственный socket супервизора.
- **Полные Web Vitals из CDP** — `PerformanceTimeline.enable` принимает только `largest-contentful-paint` и `layout-shift`; 16 из 18 типов отклоняются с `-32602`. Всё остальное — инжектированный `PerformanceObserver`.
- **Ретроспективное получение тел ответов** — вымываются **любой** навигацией, включая same-process `about:blank`. Решать надо на `requestWillBeSent` через `Network.streamResourceContent`.
- **Route extraction для Next.js App Router, SvelteKit и прод-Angular** — верифицировано на nextjs.org, vercel.com, tailwindcss.com, svelte.dev, angular.dev: роутов в рантайме нет вообще. Работает для React Router 7/8 (lazy discovery, то есть нижняя граница) и Vue/Nuxt (293 роута, полностью).
- **Воспроизводимые краулы** — невозможны. Сравнивать можно только **модель**, и то с подавлением флейка.
- **Доказательство отсутствия эксфильтрации** — невозможно. `Fetch` не видит тайминговые каналы, DNS prefetch, preconnect, WebRTC ICE.
- **Prompt injection** — не решается. У OpenAI публично «вряд ли когда-либо будет решено», у Anthropic лучший остаток 11.2%, исследование UW 2026: 4 из 7 агентных браузеров пропускают обход SOP. Маркетингового слова «safe» быть не должно.
- **Нативный UI**: OS-контекстные меню, omnibox, печать, permission-баблы, `<select>` popup на macOS, Keychain, Touch ID, CAPTCHA — недостижимы навсегда. Human handoff, и эту линию держать.

## Развороты верификации (то, что чуть не уехало в код как баг)

1. **Guard для не-аффинных iframe был математически неверен.** Старый тест сравнивал только x-компоненты, поэтому `perspective:400px` + `rotateY(45deg)` проходил как «параллелограмм»: предсказанный клик промахнулся на 32 px и попал в документ вместо кнопки. Правильный тест сравнивает **обе** компоненты обеих противоположных сторон. Аффинная модель подтверждена точной для translate/scale/rotate/skew (промах < 1 px на `rotate(25deg) scale(0.6)`). Card-flip через perspective — стандартная идиома, так что `E_NONAFFINE_FRAME` будет срабатывать в проде; полноценное решение — гомография по 4 точкам, ~30 строк.
2. **Лимит 100 МБ на pipe — только в сторону client→Chrome.** Скриншот на 125.8 МБ base64 прошёл целиком, браузер жив; а 110-мегабайтная *команда* убила соединение (`Connection closed, not enough capacity`). Ограничивать надо **исходящие** payload'ы (~64 МБ guard), а не бояться больших ответов. В CBOR-режиме входящего лимита нет вообще.
3. **`Emulation.setEmitTouchEventsForMouse`: браузер не умирает, но хуже.** Зависает не «следующий `mousePressed`», а **весь** путь мышиного ввода этой сессии навсегда, включая `mouseReleased`; выключение эмуляции не помогает, лечит только пересоздание target'а. При этом `Runtime.evaluate` и `Browser.getVersion` продолжают отвечать — то есть наивный health-check скажет, что сессия здорова, пока каждый жест молча таймаутится. Отсюда требование: глобальный per-command timeout **плюс** per-session защёлка «input path dead».
4. **`char`-шторм не воспроизвёлся** — 6 условий, оба транспорта, везде ровно один `keydown`. Понижен с «убийцы браузера» до «невоспроизведён, причина неизвестна». Гигиеническое правило (всегда заполнять `code` + `windowsVirtualKeyCode`) остаётся, оно бесплатно. Апстрим-баг без свежего репро не заводить.
5. **`Schema.getDomains` не удалён** — он работает на page-сессии (35 доменов, версия «1.2», количество плавает от того, какие агенты инстанцированы) и 404-ит только на browser-сессии. Для feature detection всё равно бесполезен, но «удалён» — фактическая ошибка, которая собьёт того, кто будет писать capability-probe.
6. **`webp` quality управляется** — 1 674 Б при q=1 против 51 944 Б при q=100 на одном клипе, вопреки описанию «jpeg only» в протоколе. Устарела документация, а не реализация.
7. **AX-скелет вырождается на div-soup.** На семантической разметке модалка видна отдельной строкой `dialog|short_text|modal|4`; на идентичном по содержанию div-супе все строки — `generic|…`/`StaticText|…`, а модалка невидима вовсе, вместе с детектором `OverlayStack`. На Википедии ~44% AX-узлов вообще без семантической роли. Fallback-скелет на DOMSnapshot нужен в v1, а не потом.
8. **Precache service worker'а — не универсальная золотая жила.** vite-pwa-org: `returnCount: 249` (не 42), из первых 200 записей 138 — `.js/.css/.wasm`; squoosh.app: 15 записей, из них route-like ровно **одна**. Выхлоп бимодальный, и в графе надо хранить `{entries, route_like}`, чтобы отчёт о покрытии не подразумевал богатый источник.

## Главные риски (полный реестр из 15 — в `00-README.md` §5)

- **Протокол resync супервизора не спроектирован.** Что происходит, когда `browserd` перезапускается посреди команды: id потеряны, супервизор их уже переслал, Chrome отвечает в пустоту, карта сессий не восстанавливается ничем. Выживание `setsid()` я подтвердил — сложная часть именно ресинк.
- **Конкурентность вообще не тестировалась.** Все эксперименты во всех семи досье — одна сессия. Ничего не проверяет две работы на одном browserd: потерю кадров screencast, блокирующий 5-секундный жест на сессии A против сессии B, 31-мегапиксельный снимок с 28.5 с кодирования, head-of-line на едином упорядоченном pipe. Это выстрелит на первой неделе.
- **Replay-from-root может не сходиться.** Исправленная оценка — ~62 минуты на краул из 300 состояний глубиной 6 (загрузка root'а + `L·(t+settle)` + обязательная двойная проверка волатильности 1.5 с). При этом **частота расхождения на ребро не измерена вообще**, а псевдокод при несовпадении сигнатуры прерывает путь: 10% на ребро — это ~47% провалов на глубине 6. **Инструмент первой недели: проиграть 50 известных путей на одном реальном приложении и померить расхождение.** Это единственное число, которое решает, жива ли архитектура краулера.
- **Politeness/robots/rate limiting отсутствуют полностью.** robots.txt парсится только ради строк `Sitemap:`. Бюджет в 2 000 действий против небольшого сайта — это self-DoS, и первый же реальный краул принесёт бан по IP или Cloudflare-челлендж.
- **Артефакты эквивалентны учётным данным.** Скриншоты залогиненных страниц, `network_json` с bearer-токенами, DOM/AX-блобы — на диск, без redaction-стадии. Отдать бандл коллеге = отдать сессию.

## Что делать первым

1. **Ответить на развилку про LLM-петлю в detached job (§4 в `00-README.md`).** Рекомендация: daemon **никогда** не зовёт модель; job всегда движется на эвристиках (нижняя граница), плюс две **разные** очереди — `needs_decision` (семантика, отвечает агент асинхронно через `brow job answer`, с TTL) и `waiting_for_approval` (необратимые действия, отвечает **только человек**, привязка к ref + document generation, TTL 15 минут, повторная проверка скриншот-диффом прямо перед выполнением, доставка — desktop notification, потому что TTY уже нет). Это блокирует форму `crates/jobs` и структуру `SKILL.md`.
2. **Ответить на Q2–Q4:** супервизор (да), headful по умолчанию (да), минимальный milestone Chrome (136).
3. **Достроить walking skeleton до честного M1.** В дереве уже есть итерации 1–2 (~7.3K строк: pipe, setsid-daemon, discovery, snapshot с `@node-N`, жесты, capture, console/network с redaction на ingest, e2e против настоящего Chromium). Не хватает четырёх вещей, и все четыре критичны: разделение на `crates/` с кодогенерацией `cdp-protocol`; счётчик document generation с отказом по устаревшему рефу; `Target.setAutoAttach`, переармленный в одном хуке, с фикстурой, где кнопка внутри cross-origin iframe реально кликается; проверка полноты фреймов (число элементов `<iframe>` против числа приаттаченных target'ов) как coverage gap.
4. **Сразу после этого — M2 (супервизор + ресинк) и M3 (двухсессионный soak-тест).** M2 не считать сделанным без прогона на реальном Linux с `systemd-run --user --scope`: корпус прямо опровергает достаточность `setsid()` там.
5. **Перед `crates/crawler` — измерить расхождение replay-from-root.** До этого числа сроки краулера не оцениваются.

Реалистичный объём спеки целиком: **~52 инженеро-недели**, из них MVP ~23, v2 ~13.5, v3 ~15.5 — не считая открытого по срокам тюнинга сигнатуры состояний и того, что навяжет измерение replay-расхождения. Два пункта из v3 стоит назвать своими именами: **cascade-winner** (origin × importance × layers × `@scope` × shadow order × source order) — это исследовательская задача, а не фича, в v1 показываем совпавшие правила по специфичности без объявления победителя; **framework adapters** — это две разные вещи, детект (тривиально, работает везде, `ng-version` читается даже из isolated world) и извлечение роутов (работает у React Router и Nuxt, невозможно у остальных без repo-aware режима).
