# brow — Research Corpus README

**Date:** 2026-08-04 · **Target:** Google Chrome 151.0.7922.72 (V8 15.1.206.10, protocol 1.3, 57 domains / 669 commands / 237 events / 616 types, 38 experimental domains) · **Host:** macOS Darwin 25.5.0 (Apple M4) · **Toolchain:** rustc/cargo 1.97.1, ffmpeg 8.1.2

---

## 1. What this is

Ten deep-research dossiers, ~12,000 lines, each written against the **live local Chrome over a real `--remote-debugging-pipe` connection** and then put through **two adversarial verification passes** that re-ran the load-bearing claims and corrected the ones that were wrong. Almost nothing here is reasoned-from-docs; where it is, it is labelled `UNVERIFIED` or `LIKELY`.

**The verification passes matter more than the original research.** Between them they refuted ~20 headline claims and materially narrowed a dozen more. At least eight would have shipped as design bugs:

- the non-affine iframe guard that mathematically could not fire (`30-` §5);
- isolated-world framework adapters, which cannot work at all (`30-` §8, `95-` §B0);
- the `Fetch`-only egress allowlist, which leaks WebSockets *and* Speculation Rules prefetch (`80-` §6.2);
- "no 16384 px texture ceiling", which is false and fails **silently with correct dimensions** (`50-` §1.4);
- attaching to `tab` targets, which is protocol-rejected *and* flushes the bfcache it was meant to observe (`10-` §3.2);
- "orphan browsers are structurally impossible", which is conditional on `FD_CLOEXEC` (`70-` §9.1);
- `Page.setWebLifecycleState{frozen}` as a pause primitive — any screenshot silently un-freezes it, permanently (`70-` §5.3);
- the AX-based crawler state signature, which is blind to **every** iframe including same-origin (`90-` §2.3).

And one finding appears in **no** dossier's original text and is the single largest week-one hazard: **only one page per browser window is `document.visibilityState === "visible"`.** Everything else runs `requestAnimationFrame` at 0 fps.

## 2. Bottom line — can brow be built as specified?

**Yes. Every hard constraint in the spec is satisfiable, and every headline feature is buildable — but five amendments must be made before code, because each changes a crate boundary or a public promise, and one of them (concurrency) is a correctness requirement that nobody has tested.**

1. **"Persistent background Chromium" + "restartable daemon" + "no TCP port" needs a fourth process — and the corpus is internally split on whether to build it.** Chrome exits `rc=0` within **0.053–1.01 s** of the fd-3 pipe reaching EOF (measured four times across three independent rigs). Whoever holds the pipe owns the browser's lifetime. `10-` §8.2 recommends a per-browser `setsid()`-detached supervisor that owns fds 3/4 and re-exports over a `0600` unix socket — **confirmed to survive `launchctl bootout` on macOS**, and **refuted for `setsid()` alone on Linux** (systemd's default `KillMode=control-group` ignores process groups; you need `systemd-run --user --scope`). `70-` §5.4, written without a supervisor, concludes flatly that no job can resume. **Both are right about their own world.** This is Q1 in §8 and it is the first thing to settle. The resync protocol on top is undesigned — that is the actual hard part, not the process.

2. **Concurrency is a correctness problem, not a scaling problem.** **Only one page per browser *window* is `document.visibilityState === "visible"`.** Every other tab in that window gets `requestAnimationFrame` at **0 fps**: zero screencast frames (a `--record-video` job records *nothing*, silently), frozen CSS animations, stalled `IntersectionObserver` lazy-loading, and an actionability stability probe that **blocks forever** (measured: 0.02 s visible → 12 s timeout hidden). `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`, `--disable-background-timer-throttling`, `Page.bringToFront`, `Emulation.setFocusEmulationEnabled` and `Page.setWebLifecycleState{active}` were **all measured ineffective**; `Emulation.setPageVisibilityOverride` does not exist. The only fix is **one `BrowserContext` (or `newWindow:true`) per concurrently-driven page**, which promotes "BrowserContext per job" from isolation hygiene to a scheduler invariant. Every experiment in all ten dossiers is single-session; this fires the first time two detached jobs run at once.

3. **The "ONE node model" is a daemon-side data structure, not a CDP call.** `DOMSnapshot.captureSnapshot` returns nothing for cross-origin frames; `DOM.getDocument{pierce:true}` gives the `<iframe>` node with a `frameId` and no `contentDocument`; `Accessibility.getFullAXTree` crosses **no** iframe, not even same-origin. Cost is O(frames) round trips plus a stitching invariant that must be a tested property, not a convention. The stitch itself is ~5 call types (algorithm in `95-` §A1); what is genuinely hard is **frame lifecycle bookkeeping** under navigation/detach races.

4. **"Raw CDP is never exposed to the agent" survives, but `evaluate` is three tiers, not two.** Verified twice, on fixtures and five live production sites: `Object.keys(node)` is **empty** in an isolated world, and `__reactFiber$*` / `__vue_app__` / `__reactRouterManifest` all read `undefined` there while DOM node counts are identical. Blink gives each world its own V8 wrapper. Framework enrichment therefore needs a **third** tier: harness-authored *fixed strings* in the **main** world, page-observable and page-tamperable, labelled as such. The agent still never supplies code. Related and undocumented anywhere until this pass: **`Page.addScriptToEvaluateOnNewDocument` bypasses the page's own CSP** — our stub ran on a document whose `script-src 'self'` blocked the page's own inline script. That is a real privilege no site can refuse and it belongs in the capability docs.

5. **The crawler must be sold as best-effort read-only, and "no telemetry" needs a proxy, not flags.** Two independent `Fetch` bypass classes were found in two attempts — WebSocket handshakes (zero `Fetch.requestPaused`, attacker server logged the 101) and Speculation Rules prefetch (`<script type="speculationrules">`, needs no JS execution at all). Both are closed by a per-`BrowserContext` CONNECT-allowlisting proxy, which *also* caught Chrome's own `CONNECT www.google.com:443` attempts **with `--disable-background-networking` already set**. So `--strict-egress` should be **default on**, and the "no cloud telemetry" hard constraint is satisfiable by the proxy and *not* by the flag set.

Three harder truths that do not change the architecture but must change the copy:

- **Every page brow touches sees `navigator.webdriver === true`**, unconditionally, because `--remote-debugging-pipe` sets it. Primary source found: `content/child/runtime_features.cc:387-389` maps `kEnableAutomation`, `kHeadless` and `kRemoteDebuggingPipe` → `EnableAutomationControlled`; lines 430-445 add `--remote-debugging-port=0`. Only an *explicit non-zero* port leaves it unset. Not opt-out-able without shipping an evasion flag. Say it in `SKILL.md`.
- **Route COVERAGE is only computable against *declared* routes with per-source provenance.** Coverage over parameterised routes is not merely hard, it is not meaningful. The spec's own instinct is exactly right and the research supports it with numbers.
- **`brow job pause` does not pause the page.** `Page.captureScreenshot` on a frozen target fires the page's `resume` event and restarts its timers, permanently, with no CDP signal; in-flight `fetch()` continuations resolve and mutate page state during the "pause"; and the page observes both `freeze` and `resume`. The only authoritative pause is the daemon-side interpreter flag.

**What is genuinely out of reach and must be removed from any promise:** canvas/WebGL/Flutter-without-semantics content enumeration (pixels only), automating the user's existing logged-in Chrome profile, per-frame screenshots of OOPIFs as isolated images, hardware-faithful IME commit, WebSocket close reasons, HAR `cache` fields, memory-leak detection, in-place job resume after a daemon restart, deterministic/reproducible crawls, Next.js App Router route extraction at runtime, and any proof that no exfiltration occurred.

## 3. Architecture Decision Record

Confidence: **confirmed** = measured or read from primary source; **likely** = strong secondary evidence; **open** = the corpus names the experiment that would settle it.

### ADR-01 — Transport is `--remote-debugging-pipe` in ASCIIZ (NUL-delimited JSON), and nothing else

**Why:** no `listen()` means no other local process can attach; single client by construction; the fds die with their holder. Wire format read from `devtools_pipe_handler.cc` and verified live: fd 3 = Chrome reads, fd 4 = Chrome writes, one `0x00` terminator per message, no length prefix. Startup to first `Browser.getVersion`: **0.19 s headless / 0.27 s headful**. Playwright defaults to pipe in production.
**Rejected:** `--remote-debugging-port` + WebSocket — reachable by every local process on the machine, no auth, defeats the no-raw-CDP invariant. CBOR mode — labelled *"Experimental (!)"* in-source, and `PipeReaderCBOR` never calls `set_max_buffer_size`, so it has **no** inbound size cap at all (a worse DoS profile than ASCIIZ's 100 MB).
**Sizing:** the 100 MB cap (`kReceiveBufferSizeForDevTools`) is **client→Chrome only** — a 125.8 MB base64 screenshot response transited intact, while a 110 MB *command* killed the browser with `Connection closed, not enough capacity`. Guard the **write** path at ~64 MB; inbound size is purely our own memory problem.
**Confidence:** confirmed · `10-` §1

### ADR-02 — Write our own CDP client; vendor `chromiumoxide_pdl`'s generator into `xtask/`; check the generated `cdp.rs` into git

**Why:** there is **no "buy" option** — every published Rust CDP crate is WebSocket-only (`chromiumoxide` 0.9.1, `headless_chrome` 1.0.22, `chromey` 2.54.0, `cdpkit` 0.5.0, `cdp-rs` 0.3.3). The pipe requirement, not the ban list, eliminates all of them; `chromiumoxide`'s pipe support is draft PR #325, still `isDraft`, with an untested Windows path. And there is **no runtime protocol descriptor over a pipe**: `Schema.getDomains` 404s on the browser session, returns 35 bare domain names at a frozen version "1.2" on a page session, and is `deprecated` (it is *not* removed — that was a corpus error). `/json/protocol` needs the HTTP port we refuse to open. `protocolVersion` has been "1.3" for years. So pin `browser_protocol.json` + `js_protocol.json` (head `r1672245`, 2026-08-01), verify their SHA-256 at build time with **no network in `build.rs`**, generate from JSON, feature-gate at runtime by milestone parsed from `Browser.getVersion.product`, and discover missing methods lazily from `-32601`.
**Sizing, measured:** an allow-list tighter than budget (93 commands + 33 events, 20 domains) pulls in **269 of 616 types (44 %)** via transitive `$ref` closure → **~37,900 lines / ~1.77 MB / ~6.7 s compile**. A realistic 195-command list reaches 381/616 types → ~62 k lines / ~2.9 MB. **Type closure, not command count, sizes the file.** Mark it `linguist-generated` and `-diff` in `.gitattributes`. Domain-level filtering is not a size strategy: the 25 domains this project needs are **76 % of the protocol by bytes** (recomputed exactly: 535,851 / 707,087).
**Rejected:** `build.rs` → `OUT_DIR` (breaks offline builds, hides protocol drift from `git diff`, mediocre in rust-analyzer); depending on `chromiumoxide` (bundles a Puppeteer-shaped handler layer that would put full CDP one `use` away from every call site); runtime `Schema.getDomains`.
**Freshness:** copy chromiumoxide's pattern — a `#[test]` that regenerates, **writes the fix, then panics**. One `cargo test` is the whole update workflow and CI catches the uncommitted diff.
**Confidence:** confirmed · `20-` §1–2, `10-` §9

### ADR-03 — Flat protocol everywhere; one process-wide monotonic `u64` id; one writer task

**Why:** non-flat (`Target.sendMessageToTarget`) is `deprecated` (crbug.com/991325). Two concurrent commands with `id:99` on different sessions both returned correctly and were distinguishable only by the echoed `sessionId` — so per-session id namespaces buy nothing and add correlation bugs. Assert the echoed `sessionId` matches what you sent; it catches routing bugs instantly. **Writes must be serialized behind one task** fed by an mpsc channel — interleaved `write_all`s from two tasks corrupt the stream.
**Routing gotcha:** `Target.detachFromTarget{sessionId:S}` sent *inside* `S` fails `-32602`; it must go to the browser session. Same for `closeTarget`, `disposeBrowserContext`, `Storage.getCookies{browserContextId}`, `Browser.setPermission`.
**In-flight death:** there is no "session closed, here are your cancelled ids" message. Every pending request needs a deadline **and** a subscription to `Target.detachedFromTarget` / `targetDestroyed` / `targetCrashed`.
**Confidence:** confirmed · `10-` §2

### ADR-04 — Chrome dies with the fd-3 holder; `FD_CLOEXEC` on both CDP fds is an asserted, unit-tested invariant

**Why:** measured four ways — closing the parent's fd-3 write end exits Chrome `rc=0` in **0.053 s** (one rig) / **1.01 s** (another, 2/2 runs), and **1.00 s even with a renderer spinning in a 120 s busy loop**. The control isolates the mechanism: closing only the fd-4 *read* end left Chrome `STILL ALIVE after 45.3 s` in state `Ss`. **But "orphans are structurally impossible" is REFUTED as stated.** A pipe reader sees EOF only when *every* write end closes: with `/bin/sleep 120` holding an inherited duplicate, `CHROME STILL ALIVE after 40.2 s <== ORPHAN`. `browserd` **will** spawn ffmpeg for `--record-video`; any spawn path without `FD_CLOEXEC` orphans a ~2 GB browser on every recording job.
**Note:** `tokio::net::unix::pipe::Sender::from_owned_fd` does **not** set CLOEXEC for you, and `command_fds`' `FdMapping` only handles the child's copy — the *retained* `Sender`/`Receiver` fds are the ones at risk. Keep the `ppid==1` + `--user-data-dir` match + `kill(-pgid)` sweep as a backstop. `Browser.close` (~163 ms) remains the graceful path because it flushes the profile.
**Implementer note that costs an hour on day one:** the fd pre-flight (`AreFileDescriptorsOpen()`, Chrome ≥136) fails even with correct `posix_spawn` `DUP2` file actions unless you clear `FD_CLOEXEC` on the *source* fds first. Rust's `nix::unistd::pipe()` sets `O_CLOEXEC` by default; `Command::pre_exec` + `libc::dup2` clears it on the new fd (so the `10-` §1.6 snippet is correct), but a switch to `posix_spawn` for speed hits this immediately. Error string: `chrome_main_delegate.cc:1101 Remote debugging pipe file descriptors are not open.`
**Confidence:** confirmed · `20-` §Limits 1, `70-` §9.1, `10-` §8.1

### ADR-05 — A per-browser `brow-supervisor`, `setsid()`-detached, owns fds 3/4 and re-exports over a `0600` unix socket — **conditional on Q1**

**Why:** it is the only way to have persistent Chromium **and** a restartable daemon **and** no TCP port simultaneously. It is also the only component that touches raw CDP framing, so "no raw CDP to the agent" becomes a **process boundary**, not a code convention.
**Platform detail:** macOS confirmed empirically — a real LaunchAgent's `setsid()`'d grandchild survived `launchctl bootout` while the same-pgid sibling died; `man 5 launchd.plist` documents PGID-based reaping and `AbandonProcessGroup` is not even required. **Linux refuted from primary source** — `systemd.kill(5)` defaults to `KillMode=control-group` and process groups are irrelevant to cgroups; use `systemd-run --user --scope --unit=brow-sup-<id>` (or D-Bus `StartTransientUnit`). Windows job objects are the same class of risk (`CREATE_BREAKAWAY_FROM_JOB`), untested.
**Rejected:** `browserd` holds the pipe (every daemon restart kills every browser — this is `70-`'s world, and it is a coherent, simpler product if the owner accepts it); TCP port (security); `SCM_RIGHTS` fd handoff (works for planned handoffs only, not crash recovery, and the surviving holder is precisely the orphan condition in ADR-04).
**Confidence:** confirmed on macOS / refuted-and-corrected on Linux / **the reconnect-and-resync protocol is open, and it is the hard half** · `10-` §8.2 vs `70-` §5.4

### ADR-06 — Recursive `Target.setAutoAttach{autoAttach, waitForDebuggerOnStart:true, flatten:true, filter}` re-armed in exactly one `on_attached()` hook; **never** attach to `tab` targets

**Why:** auto-attach reaches only *immediate* children, so A→B→C needs three calls. A cross-origin iframe is completely invisible from the parent session (`iframe.contentDocument === null`, verified). A missed re-arm silently drops an entire subtree — the worst possible failure mode for a tool selling "complete introspection". `waitForDebuggerOnStart:true` costs a round trip per target and is mandatory: without it you race the renderer and lose early network/console events, and a service worker can issue requests before `Fetch.enable` lands.
**`tab` targets are answered NO, three ways:** (a) `Target.setAutoAttach` rejects any filter admitting both — `-32602 "Filter should not simultaneously allow \"tab\" and \"page\""`; (b) a tab session answers only `Target.getTargetInfo/getTargets/setAutoAttach` — 14 other methods probed, all `-32601`; (c) **tab-routed attach flushes the bfcache** (`pageshow persisted=false` + `Page.backForwardCacheNotUsed{reason:"CacheFlushed"}` vs `persisted=true` on direct page attach), destroying the transition it was supposed to observe.
**Replacement recipe:** detect bfcache restore from the page session — `frameStartedNavigating` + `frameNavigated` + `frameStarted/StoppedLoading` + `executionContextsCleared/Created` and **no `loadEventFired`, no `domContentEventFired`** (a normal navigation fires both); sessionId and target survive. `Page.backForwardCacheNotUsed{notRestoredExplanations[], notRestoredExplanationsTree}` is a free, machine-readable, per-frame *why not* — exactly the `declared|observed|discovered|inferred|blocked` provenance the spec asks for. Prerender goes through `Preload.enable` (works on a page session) plus `TargetInfo.subtype=="prerender"`.
**Corollary the corpus flags as missing and cheap:** compare the `<iframe>`/`<frame>` element count per session against attached iframe targets + same-process `contentDocument`s, and report the delta as a coverage gap. Without it, "route COVERAGE and provenance" has no foundation at the frame level. Also filter the built-in component extension — a fresh scratch profile with **no** extension flags always carries `chrome-extension://nkeimhogjdpnpccoofpliimaahmaaome/background.html`, type `background_page`, under its own `tab` target, so any "how many targets does this job own" assertion is off by one from day one.
**Confidence:** confirmed · `10-` §3.2–3.3, `30-` §5

### ADR-07 — One `BrowserContext` (or `newWindow:true`) per **concurrently-driven page** — a scheduler invariant, not an isolation nicety

**Why:** two separate arguments now converge on the same rule.
*Isolation:* measured full cookie + localStorage + permission isolation; `Storage.*` and `Browser.setPermission` are `browserContextId`-scoped; `createBrowserContext` also takes `proxyServer`/`proxyBypassList` (per-job proxying without relaunching — the egress layer in ADR-19 depends on it). An empty context is ~free; a live page costs ~149 MB with or without its own context, versus ~505 MB + 6 processes for a second browser.
*Correctness:* only one page per browser **window** is `visible`. Measured on headless Chrome 151 with a rAF counter over 1 s — two pages in one context: `A=hidden/0fps, B=visible/60fps`; `Target.activateTarget(A)` **swaps** rather than adds; pages in separate contexts: all `visible` at 60 fps. Downstream: a hidden tab yields **zero** screencast frames (an idle visible tab gave 240 frames / 60.4 fps / max gap 27.9 ms), and the in-page double-rAF actionability probe never returns. `Page.captureScreenshot` still works on a hidden tab (each capture appears to pump one frame), so still-shot jobs are unaffected — only video and anything time-based.
**But BrowserContexts cannot be persisted to disk.** Only the default context in the user-data-dir is durable. So **named `--user-data-dir` profiles are a first-class concept**, not an escape hatch, and they are the only mechanism behind the site mapper's auth-branch ambition. Sharp edge to document: a fresh context inside a logged-in profile inherits **nothing** — `--profile work` + `--isolated-context` = logged out. You get the session or the isolation, not both.
**Confidence:** confirmed · `10-` §4.2, `50-` §4.1, `40-` §12, `80-` §7.3

### ADR-08 — Node ref = daemon-allocated `@nN` over `(target_id, frame_id, doc_generation, backend_node_id)` + a re-resolution fallback; never trust `backend_node_id` alone

**Why:** this is the **highest-severity correctness risk in the whole corpus.** `nodeId` dies on reparent. `backendNodeId` survives reparent *and survives same-process navigation* — after which `DOM.describeNode`, `DOM.getBoxModel` and `DOM.scrollIntoViewIfNeeded` all **succeed** and return **byte-identical stale geometry** with no error (reproduced deterministically on two independent fixtures; the returned box was the pre-navigation box to the decimal). Only `DOM.resolveNode` errors, with `-32000 "Node with given id does not belong to the document"` — **match on the code, not the message.** Cross-origin navigation does invalidate (new renderer process), which is exactly why the bug hides. Without a generation counter the harness will eventually click coordinates from the previous page.
`backendNodeId` is also only unique per renderer process, so the primary key is `(target_id, backend_node_id)`. Refs shown to the agent are daemon-allocated so two frames cannot collide.
**Also:** always `Runtime.releaseObjectGroup` after an inspection batch — retained `RemoteObject`s keep stale nodes alive and resolvable. `DOMDebugger.getEventListeners` alone holds ~2× the listener count in handles.
**Industry corroboration:** Google's `chrome-devtools-mcp` independently arrived at the same key — `TextSnapshot.ts` reuses a uid while `` `${loaderId}_${backendNodeId}` `` is unchanged. Adopt `@e<N>` or `@nN`; the idiom is established and models already know it.
**Confidence:** confirmed · `30-` §1, `95-` §A1

### ADR-09 — Unified tree = `DOMSnapshot.captureSnapshot` (bulk) + `DOM.getDocument{pierce:true}` (structure/identity) + per-frame `Accessibility.getFullAXTree` (enrichment) + one whole-page listener call, stitched via `DOM.getFrameOwner` from the **parent** session

**Why:** 211 ms for 19,707 nodes on Wikipedia, replacing ~16 K per-node round trips; struct-of-arrays with a shared string table (only 14,457 strings for Wikipedia — reuse it, don't re-intern). AX is an *enrichment layer* keyed by `backendDOMNodeId`, not the base: raw `getFullAXTree` on Wikipedia is **9.28 MB**, larger than both the snapshot (4.01 MB) and `getDocument{pierce}` (3.86 MB); stripping `name.sources`/`chromeRole`/`ignoredReasons` halves it (github.com 888,206 → 440,224 B). Byte counts replicated to within 0.1 % on an independent run; node counts identical to the unit.
**Refinements from verification:** `getFullAXTree{frameId}` works for **same-origin** children *from the same session*, so the cost is one AX call per frame *in the process* — only true OOPIFs need their own session. `DOMDebugger.getEventListeners{objectId:<document>, depth:-1, pierce:true}` really does return the whole-page listener map in **one call, ~10 ms, ~180 KB** on github.com (1,007 listeners / 2,394 elements) and Wikipedia (1,161 / 9,534) — crossing closed shadow roots and same-origin iframes. The brief's assumption that this is per-node and expensive is wrong. Filter `shadowRootType=="user-agent"` (one `<input type=date>` + one `<video controls>` produced **21** UA roots and `DOM.getDocument` has no suppression flag — its parameters are exactly `[depth, pierce]`).
**Parse with `serde_json`, not `simd-json`.** Benchmarked on the real payloads: the 4.36 MB snapshot is 9.42–12.08 ms with `serde_json` vs 9.80–11.78 ms with `simd-json` — **a wash**, and 5 % of the 211 ms Chrome spends producing it. The only win is on the AX tree, which the design says never to keep raw.
**Confidence:** confirmed · `30-` §2, §3, §7, §12

### ADR-10 — Cross-frame coordinates via an affine basis from the owner iframe's **content** quad ÷ the child's `clientWidth/Height`, guarded by a **both-axes** parallelogram test

**Why:** verified exact for translate/scale/rotate/skew — a predicted click under `rotate(25deg) scale(0.6)` landed within 1 px; naive origin-addition missed a scaled iframe entirely. **The guard originally proposed was mathematically wrong**: it compared only x-components, so a `perspective:400px` + `rotateY(45deg)` frame passed as "affine" and the click landed 32 px off, on the document instead of the button. Correct test: `TL→TR` must equal `BL→BR` in **both** components (`q1-q0 == q2-q3` for a quad ordered TL,TR,BR,BL). Measured: the old detector flagged **neither** frame; the corrected one flags the perspective frame (Δy = 69.31) and correctly passes the rotated one (Δ = 0,0).
`perspective` + `rotateY` is the standard card-flip/carousel idiom, so `E_NONAFFINE_FRAME` **will** fire in the wild. A 4-point homography (~30 lines) would actually solve it and is the right follow-up.
**Two coordinate-space facts that must be encoded once and tested:** CDP geometry and `Input` coordinates are **layout-viewport CSS px** and are unaffected by `deviceScaleFactor` *and* by `pageScaleFactor` (verified under `setPageScaleFactor{2.0}`: visual viewport 400×300, layout 800×600, a click at the quad centre `(250,425)` arrived as `clientX/Y = 250,425`). And `DOMSnapshot.layout.bounds` is **document** space while `getBoxModel`/`getContentQuads`/`getNodeForLocation`/`Input.*` are **viewport** space.
**Confidence:** confirmed (algorithm and corrected guard, both measured) · `30-` §5, `40-` §1, `50-` Limits #11

### ADR-11 — Agent-facing output is tiered: compact line-oriented interactive view by default (viewport-scoped, paged) → fat node ≤ 900 tokens on demand → raw dumps to artifacts with server-side query

**Why:** measured. github.com: 253 elements = **22,343 bytes ≈ 6.0 K tokens** compacted, versus 168–246 K raw. One raw fat node on github.com ≈ **309 K tokens** (`CSS.getMatchedStylesForNode` 985 KB, of which `inherited` alone was **1,062,842 bytes across 11 entries**; computed style = 2,465 properties, 1,984 of them custom properties, 154 KB for one node). **Do not make the fat tree the default output.** Prior art agrees: an AX-shaped projection is a few hundred lines, a fat tree with CSS + listeners + layout + paint order is 10–50×, and there is no 2026 evidence that models use CSS cascade or paint order well. ### ADR-12 — All input points resolve through `DOM.getContentQuads`; every click is `mouseMoved` → `mousePressed` → `mouseReleased`

**Why:** quads are true rotated parallelograms (not bboxes), `{quads:[]}` for `display:none` (that is your "not visible" signal), live and viewport-relative, and already composed to main-frame coordinates for same-origin iframes. Skipping `mouseMoved` still synthesizes over/enter but with an impossible `buttons:1` and **no `mousemove` at all**, which breaks hover menus, drag thresholds, tooltip timers, canvas cursors, and `dnd-kit` activation constraints.
**OOPIF:** compose offsets in the parent for hit-testing (only the parent can see a parent-page overlay covering the frame), dispatch on the frame's **own** session with frame-local coords. Both verified.
**Modifier bitmask, verified:** `Alt=1, Ctrl=2, Meta=4, Shift=8`. `clickCount` is honoured *mechanically, not temporally* — dispatching 1 then 2 back-to-back with zero delay produces `click(detail 2)` + `dblclick`. Convenient, but the harness never exercises the real timing path, so offer an optional inter-click delay.
**Confidence:** confirmed · `40-` §1–2

### ADR-13 — `Emulation.setEmitTouchEventsForMouse` is banned by a compile-time test; mobile = `setTouchEmulationEnabled` + explicit `dispatchTouchEvent`

**Why:** after enabling it, `mousePressed` never resolves. Verification **widened the blast radius and narrowed the symptom**: *every* subsequent `Input.dispatchMouseEvent` on that session hangs including `mouseReleased`; turning the emulation back off does **not** recover it; only `Target.closeTarget` + recreate does. The browser process does **not** die (the original "browser gone" reading was harness teardown), and `Runtime.evaluate` / `Browser.getVersion` keep answering — **so a naive health check reports the session healthy while every gesture silently times out.** crbug 40225266, open since 2022.
**Design requirement this forces:** a global per-command CDP timeout **plus** a per-session "input path dead" latch that fails fast and recommends target recreation.
**Also confirmed, contradicting the brief:** `dispatchTouchEvent` works *without* touch emulation (delivered `pointerdown/touchstart/touchend/click`, all `isTrusted:true`, on a target with `maxTouchPoints===0`). Emulation is a **feature-detection** prerequisite — sites gate handler binding on `'ontouchstart' in window` — not a delivery one.
**Downgraded:** the `type:"char"` keydown storm **did not reproduce** across six conditions and both transports (every variant gave exactly 1 `keydown`, browser alive). Keep the zero-cost hygiene rule (always populate `code` + `windowsVirtualKeyCode` on `char`; prefer `keyDown{text}` entirely) but drop "browser-killer" from any user-facing text and do **not** file upstream without a fresh repro.
**Confidence:** confirmed · `40-` §11, Limits 1–2

### ADR-15 — Actionability is our problem, and it must be **reportable**, never a silent retry

**Why:** this is the single largest thing Playwright absorbs. Order: ref-generation → enabled/editable from the tree (no eval) → quads → viewport → **in-page isolated-world two-rAF stability** → clipped action point → hit test in the **main** session. Measured: the CDP-awaited double-rAF costs 3 round trips and spans 14–47 ms of wall clock; the in-page version is 1 RTT with correct ~4 px frame granularity, and the isolated world means the page cannot observe or patch the probe.
**Defect found and fixed:** the bare `awaitPromise` rAF probe **blocks forever** on any page that is not the active tab of its window (0.02 s visible → 12 s timeout hidden). Three required changes: (a) ADR-07's one-window-per-page rule; (b) race the probe against an in-page timer — `Promise.race([twoRafs, new Promise(r=>setTimeout(()=>r("hidden-no-raf"),250))])` — and surface `hidden-no-raf` as a *distinct* actionability outcome; (c) a 5 s budget made of 30 s hangs is not a budget.
**More generally:** CDP provides **no server-side timeout** for `Runtime.evaluate{awaitPromise:true}`. A promise that never settles pins a request slot until the client's own deadline. Every awaited evaluate needs an in-page `Promise.race` **and** a client deadline. `Runtime.evaluate{timeout:2000}` genuinely terminates `for(;;){i++}` in 2008 ms — it is a usable DoS control and is mandatory on `mutate.evaluate`.
**Failure must return** `StaleRef | Disabled | ReadOnly | NotVisible | OffScreen | Unstable | HiddenNoRaf | Occluded{by}` plus an annotated screenshot naming the culprit (`occluded by @e9 (role=dialog, "Cookie preferences") at (412,318)`). That error object is what lets an agent self-correct instead of retrying blindly. Caveat found the hard way: a single "stable" reading proves nothing on short transitions — pair it with a minimum settle time after any action that could start an animation.
**Auto-wait constants to clone** (from `chrome-devtools-mcp`'s `WaitForHelper`, Apache-2.0, verified verbatim): `stableDomTimeout 3000 ms`, `stableDomFor 100 ms` (MutationObserver quiet period on `document.body`), `expectNavigationIn 100 ms`, `navigationTimeout 3000 ms`, filtering `Page.frameStartedNavigating` by `navigationType ∉ {historySameDocument, historyDifferentDocument, sameDocument}`. It includes a dialog guard because dialogs **pause the renderer** and would otherwise hang `evaluate` for the 180 s protocol timeout while a mutex is held.
**Confidence:** confirmed · `40-` §12, `95-` §A1–A2

### ADR-16 — Capture: full page = `scrollTo(0,0)` + `captureBeyondViewport:true` + explicit clip; node shot = `getContentQuads` → union bbox → **add `cssLayoutViewport.pageX/pageY`** → clip; **cap output dimensions at 16384 px on both axes and tile**

**Why (coordinates):** two spaces, and mixing them is the most likely geometry bug in the project. `getContentQuads` is **viewport**-relative (goes negative: y0 = 720 / 320 / **−280** at scroll 0 / 400 / 1000); `captureScreenshot.clip` is **page**-absolute (byte-identical PNGs at scrollY 0 vs 1000). Omitting the scroll add passes every test written at scroll 0 and corrupts silently later. Use `getBoxModel(iframe).content` — **not** `getContentQuads` — for the frame offset chain: measured on a 10 px-bordered 300×200 frame, quads returned `[70,300 … 390,520]` (border box) and content returned `[80,310 … 380,510]`. Use `getContentQuads` for the *target* node because `getBoxModel` collapses fragmented inlines (1 union box vs the correct 3 line boxes).
**Why (the 16384 wrap — the most dangerous single fact in the corpus):** above **16384 output device pixels** in either axis (`dim × clip.scale × deviceScaleFactor`), `Page.captureScreenshot` returns an image of the *requested* dimensions whose rows/columns ≥ 16384 are a **verbatim repeat of rows 0..16383**. No error, no truncation. Verified by colour-banding: H=16384 all 5 bands correct; H=16600 red reappears at exactly 16384 and magenta is missing; H=200000 the red band repeats 13× at multiples of 16384 and four bands are absent. Symmetric on width. Identical in headless **and** headful GPU on Apple Silicon. `CSS 20000 @ scale 0.5` (= 10000 out) is **correct**; `CSS 9000 @ scale 2` and `CSS 10000 @ dsf 2` are **not**. **A megapixel cap does not catch this** — 800×20000 is 16 MP and already corrupt. Cap the output dimension and either tile (preserves resolution) or auto-reduce `clip.scale` (verified correct, loses resolution). Ship a `brow doctor` self-check that captures past the bound and asserts a known bottom marker, and record `capture_tiled` + output dimensions in every manifest so legacy corrupt artifacts are identifiable retroactively.
**Other confirmed mechanics:** `position:fixed` is **not** duplicated in a full-page shot — exactly one band, at `y == scrollY`, reproduced on two independent fixtures — so `scrollTo(0,0)` is the entire fix. `captureBeyondViewport` does **not** drive lazy loading (an `<img loading=lazy>` 9000 px down stayed `[complete=false, naturalWidth=0]` before *and* after capture); `--prime-scroll` is the only fix and it mutates page state, so it must be opt-in with `lazy_primed` in the manifest. `webp` **quality is honoured** despite the protocol saying jpeg-only (1,784 / 1,866 / 42,306 B at q1/q50/q100 — a 24× spread); probe it at startup rather than trusting either. `Page.captureScreenshot` on an OOPIF session is rejected `-32000 "Command can only be executed on top-level targets"` — "per-frame" means *the region of the top-level page where that frame lives*, including whatever the parent paints over it. Draw annotations ourselves (`tiny-skia` + `ab_glyph`) — `Overlay.highlightNode` renders and reverts cleanly but injects a ~163×133 px DevTools tooltip with an ACCESSIBILITY block that **occludes page content** and auto-places itself.
**Confidence:** confirmed · `50-` §1–3

### ADR-17 — Video = screencast JPEG → frame directory **first** → optional ffmpeg mux; the JSONL action log is the timing source of truth

**Why:** the ladder is **two rungs, not three** — ffmpeg, or frames-on-disk. The pure-Rust middle rung does not exist: `image-webp` 0.2.4's encoder has **zero** `ANIM`/`ANMF` support and `encode()` consumes `self` for a single frame; `rav1e` is AV1 and far too slow; `vpx-encode` is unmaintained since 2022; MJPEG-in-MP4 via `mp4-atom` plays in Safari/QuickTime/VLC but **not in Chrome or Firefox** and is ~40× larger. That promotes `frames/NNNNNN.jpg` + `frames.jsonl` to the **only guaranteed artifact** and makes `brow job artifacts <id> --mux` a first-class command. Write frames first so a crash mid-recording still leaves usable artifacts — and an agent can read frames directly, which is arguably the most useful rung for the actual consumer.
**ffmpeg traps, measured:** `-fps_mode vfr` silently collapses 282 frames to 103; `-r` on input destroys durations (0.283 s); only **`-fps_mode passthrough`** preserves all 283 at 4.040 s. `libx264` fails with `error -22` on odd heights, which screencast produces routinely — the even-dimension scale filter is not optional. Use `ffmpeg-sidecar` 2.5.2 with **`default-features = false`**: its default feature is `download_ffmpeg`, which pulls `ureq`/`zip`/`tar`/`xz2` and **fetches a binary over the network**, a direct violation of a hard constraint.
**Timing honesty:** video PTS quantizes to **~20 ms** (max error 19.8 ms, mean 9.7 ms) — *identical in MP4 and WebM*, so it is the concat demuxer's timebase, not the container — while the action log is accurate to ~**2 ms**. State both numbers; never conflate them. `screencastFrame.sessionId` is documented as "Frame number" and is **constant 1** across 343 and 240 frames in two runs — maintain your own `frame_index` and never claim a recording is complete. `screencastFrameAck` is mandatory (un-acked streams stall after 3 frames). Screencast is damage-driven: a static page emits **zero** frames, so duration comes from explicit start/stop timestamps, never `frame_count / fps`.
**Clock:** screencast and `Input` timestamps are already host wall-clock epoch seconds (measured skew **1.5 ms**); `Network.requestWillBeSent` carries **both** clocks for the same instant and is the free Rosetta stone for `MonotonicTime`.
**Confidence:** confirmed · `50-` §4, `20-` §7

### ADR-18 — Events: three error streams with cross-stream dedup; all timestamps normalised to monotonic µs at ingest; vitals and mutations from injected isolated-world observers; bodies decided at `requestWillBeSent`

**Why (three streams):** `Runtime.consoleAPICalled` and `Log.entryAdded` are **disjoint** for `console.*` (36 vs 6 events, zero overlap — there is nothing to dedupe *there*), but `Audits.issueAdded` is a third source and it is the **only** structured source for deprecations, cookie exclusion reasons, CSP `violatedDirective` and CORS `corsError`. Deprecations reach `Log.entryAdded` **never** — an `unload` handler produced `Audits{DeprecationIssue}` + `Network.reportingApiReportAdded{type:"deprecation"}` and zero Log entries. Cross-stream dedup **is** required: one CSP violation fires 2 events, one CORS failure fires **4**, and the *explanatory* CORS message has `source:"javascript", category:"cors"` — filter on `source=="network"` and you keep the useless `net::ERR_FAILED` line and drop the explanation.
**Why (clocks):** Runtime/Log are **wall-ms**, Network/Page/Performance are **monotonic-s**, trace is **monotonic-µs**, `PerformanceObserver` entries are ms-relative-to-`timeOrigin`, and `Audits.issueAdded` / `*ExtraInfo` / `Page.frameNavigated` / `Runtime.executionContext*` carry **no timestamp at all**. "Sort by monotonic" is not implementable. The calibration primitive is `requestWillBeSent.wallTime − .timestamp`, free on every request, **measured stable to 16 µs** over 6 samples and cross-checked three ways. Stamp timestamp-less events with daemon receipt time flagged `clock:"receipt"` and never render them as precisely interleaved. Emit a `clock.jump` event on >100 ms offset steps.
**Why (vitals):** `PerformanceTimeline.enable` accepts **only** `largest-contentful-paint` and `layout-shift`; 16 other types return `-32602`, and `TimelineEvent` structurally carries only `lcpDetails`/`layoutShiftDetails`. FCP/INP/TTFB/longtask/LoAF **require** an injected `PerformanceObserver` (15 supported types; `observe()` on an unsupported type **silently no-ops** rather than throwing, so always gate on `supportedEntryTypes`). Compute INP and CLS ourselves (~120 lines); do not vendor the `web-vitals` npm library.
**Why (mutations):** CDP `DOM.*` events deliver **counts, not content** — 5,651 `childNodeCountUpdated` and exactly **one** `childNodeInserted`, 775 KB / 3 s — versus an isolated-world `MutationObserver` at 2,976 real records in **438 bytes**: a ~1,770× reduction at higher fidelity. Use `DOM.enable` only transiently while building the tree.
**Why (bodies):** response bodies are evicted by **any** navigation, including a same-process `about:blank` — this is the guaranteed outcome, not a race. Subscribe `Network.streamResourceContent` in the `requestWillBeSent` handler with no Fetch interception, and **concatenate `bufferedData` with the inline `dataReceived.data` chunks**: for a 3 MB body only 2 of 28 chunks carried inline data, so chunks alone lose 1,074,177 bytes (35 %) **silently**. Small/fast resources finish inside the subscribe RTT and return `-32602 "Request with the provided ID has already finished loading"` — that is the signal to fall back to `getResponseBody`, not an error. And you **cannot** have both un-perturbed timings and guaranteed bodies: `Fetch` interception pauses every response and corrupts the very timing the harness exists to report. Pick per job and label the artifact with which mode ran.
**Trace:** slim categories + `streamCompression:"gzip"` = 81,811 compressed / 768,004 raw bytes / 4,032 events per 3 s (**9.4×**, ~27 KB/s) versus 10 MB for a DevTools-ish set. `Tracing.start` must go to the **browser** session (a page session reset the connection). Trace `ts` shares the network monotonic base **exactly** (`firstContentfulPaint` vs `domContentEventFired` agreed to **294 µs**) and `ResourceSendRequest.args.data.requestId` is **byte-identical** to `Network.requestId` — trace↔network is a join, not a heuristic. Filter `ph=="M"` before any time-range math (50 metadata events had `ts==0`). Write our own ~200-line parser; no maintained Rust crate exists.
**Confidence:** confirmed · `60-` §1, §4, §8, §9

### ADR-19 — Evaluate is **three** tiers, and egress needs **three layers**

| Tier | Mechanism | Boundary |
|---|---|---|
| `inspect.evaluate` | `Runtime.evaluate{throwOnSideEffect:true, silent:true, awaitPromise:false, timeout:2000}` in an isolated world | **Real.** 32 targeted probes across two passes — 12 mutation bypasses (`Reflect.set`, `eval`, `Function()`, `setTimeout`, `Promise.then`, dynamic `import()`, `String.replace` callback, `toString` hijack, Proxy get-trap, `structuredClone`, `forEach(e=>e.remove())`, array mutation) and 20 egress probes targeting the `HasSideEffectToReceiver` exemption (`new Image().src=…+document.cookie`, `new Audio`, `new WebSocket`, `new EventSource`, `sendBeacon`, `fetch`, `import('http://…')`, `script.src=`, `link[rel=preload].href`, `new FontFace().load()`, XHR, `serviceWorker.register`, `caches.open`, `window.open`, `location.href=`, `form.submit`, `form.requestSubmit`, detached `innerHTML='<img src=…>'`) — **all blocked in ≤1 ms, zero attacker-server hits.** ~0.05 ms/call |
| `inspect.routes` (**new — forced by the corpus**) | Harness-authored *fixed strings* in the **main** world | None. Page-observable, page-tamperable, and it bypasses the page's CSP. Agent never supplies the code |
| `mutate.evaluate` | `Runtime.evaluate` (no side-effect flag), per-origin, inside an already-closed egress allowlist, full audit record | None in-page. Equivalent to a shell for that origin |

**Caveats to ship:** `throwOnSideEffect` protects **integrity, not confidentiality** — it happily returns `input[type=password].value` → `hunter2`. It is over-conservative (`getElementById`, `elementFromPoint`, `localStorage.getItem`, `indexedDB.databases()`, `crypto.getRandomValues`, `performance.mark` all rejected while `querySelector` is allowed) — so rewrite common patterns in Rust, or (better) ship typed read verbs and make free-form read-only JS the escape hatch. And it is **EXPERIMENTAL and was never designed as a security boundary** — it is a V8 correctness mechanism for DevTools eager-eval, and brow would be among the first to treat it as a boundary. Ship a 6-expression boot canary (3 must pass, 3 must throw) that refuses to expose `inspect.evaluate` on regression. The canary catches API regressions, not V8 bugs.
**Egress, three layers, because one is provably insufficient:** (a) per-target `Fetch.requestPaused` allowlist on **every** attached session — page, OOPIF, `worker`, `service_worker` — never browser-session-only (browser-session `Fetch` caught exactly one request, the top-level Document, and merely *duplicates* per-target pauses where both are on; `Network.enable` does not exist on the browser session at all). Verified blocking of `Document`, `XHR`, `Image`, `Script`, `Ping` (`sendBeacon`, incl. on `pagehide`/`visibilitychange`), `EventSource` (arrives as `XHR`, not `EventSource`), cross-origin form POST (arrives as `Document`), `<link rel=prefetch>`, and **service-worker-initiated `fetch()`** (the load-bearing fix — invisible to a page-session Fetch). (b) a per-`BrowserContext` **CONNECT-allowlisting proxy** (`proxyServer` + `proxyBypassList:"<-loopback>"`), the only layer that sees WebSockets and Speculation Rules prefetch — and Chrome's own background connections. (c) injected `Content-Security-Policy: connect-src 'self' …` on the top-level Document via `Fetch.getResponseBody` + **`Fetch.fulfillRequest`** — `Fetch.continueResponse` does **not** work for this (headers alone error `-32000`; with both code and headers it returns `{}` and the CSP is not applied).
**Proxy design detail learned the hard way:** returning `403` for a denied request makes `fetch(url,{mode:'no-cors'})` **resolve** — the page and your agent cannot distinguish a block from a legitimate opaque response. **Reset the connection instead.** Canonicalize hosts: `localhost` and `127.0.0.1` are **different hosts** to the matcher.
**Confidence:** confirmed on every enforcement primitive · `80-` §4, §6; `30-` §8; `90-` §3.4

### ADR-20 — Policy: capability lattice `observe ⊂ interact ⊂ {inspect, storage} ⊂ mutate ⊂ control`; the verb→capability table **is** the allowlist; three merged layers with deny-always-wins; default grant `observe+inspect` on an ephemeral profile

**Why:** the verb table is what makes "no raw CDP" true — if a verb is not in the table it does not exist, and there is deliberately no `cdp raw`, no `cookies import-from-chrome`, no `attach --pid`, no `launch --no-sandbox`, no `eval --unsafe-csp`, no `bypass-csp`, no `ignore-cert-errors`, no `context new --universal-network-access`. Merge-not-override with deny-wins is Claude Code's semantics; the managed tier gives teams a lock. Ephemeral (logged-out) default mirrors Atlas's published guidance and is the single highest-leverage default: **a job with no session cannot leak one.** Keep gstack's deny-default CDP allowlist as an *internal* invariant even though no raw command ships — it makes the policy auditable via `browserctl <cmd> --explain`.
**Approvals bind to node ref + document generation**, are `--once` by default, expire (15 min proposed), and are **re-verified by screenshot diff against the approval evidence immediately before execution** — an SPA can re-render between approval and click, and framework virtual-DOM reuse can change what `@node-42` visually is without changing the generation. **Capture evidence BEFORE freezing**, never freeze-then-screenshot (ADR-21).
**Per-job bearer capability token** (32 random bytes, `0600`) on every IPC call in addition to the `LOCAL_PEERCRED` uid check: the uid authenticates the *user*, not the *job*, and without a token any process the user runs inherits the most-privileged live job's capabilities. `UnixStream::peer_cred()` returns a real cross-process **pid** on macOS (verified with a genuinely separate client via `LOCAL_PEERPID`) — log it for audit, but it is **not** an authorization gate (TOCTOU-racy against `exec`, defeatable by `DYLD_INSERT_LIBRARIES`).
**Hard-blocked:** `Target.exposeDevToolsProtocol` (injects a `window.cdp` binding) needs a compile-time test asserting the string never appears in any allowed capability path. Same for `FORBIDDEN_FLAGS` (`--no-sandbox`, `--disable-web-security`, `--disable-features=IsolateOrigins,site-per-process`, `--remote-debugging-port`, …), non-overridable by `policy.toml`.
**Refuse to build cookie import from the user's real Chrome.** It is technically implementable on macOS (AES-128-CBC, PBKDF2 salt `saltysalt`, 1003 iterations, passphrase from the `Chrome Safe Storage` Keychain item) and it is the infostealer kill chain verbatim — it launders one Keychain prompt into permanent all-site access and cannot be scoped per job. Chrome ≥136 broke the debugging path deliberately (blog re-fetched 2026-08-04; both switches covered; Chrome for Testing exempt). **Document the refusal in `SKILL.md`** so the agent does not go shell out to a stealer script when the verb is missing. *(Do not write "the encryption key is bound to the data directory" — unsupported on macOS, where OSCrypt uses one app-wide Keychain item; App-Bound Encryption is Windows-only.)*
**Confidence:** likely (the lattice) / confirmed (every enforcement primitive) · `80-` §2–3, §7

### ADR-21 — `pause` is a daemon-side interpreter flag; `Page.setWebLifecycleState{frozen}` is a best-effort timer quiesce, not a pause

**Why:** freeze works (a `setInterval` counter held at 120 for 2.0 s) — but **`Page.captureScreenshot` silently and permanently un-freezes it**: immediately after a successful 28 ms capture, `LC=["f@…596078","r@1785869598092"]` and `n` resumed 120→126→129, with **no CDP signal and never re-frozen**. A control with no CDP traffic for 4 s held the freeze. Also: an in-flight `fetch()` to a 3 s endpoint **resolved during the freeze** and mutated `window.F`; and the page observes **both** `freeze` and `resume`, so an adversarial page gets a reliable "the agent just paused and screenshotted me" signal.
**Rejected:** `Emulation.setVirtualTimePolicy{policy:"pause"}` — verified a **one-way door**: `{policy:"advance"}` with no budget ran the page **~8,800× real time** (counter 131 → 439,809 in 0.5 s wall), budget expiry re-pauses, and the enum is exactly `[advance, pause, pauseIfNetworkFetchesPending]` — there is no `disable`. `Debugger.pause` poisons the session.
**Revised recipe:** capture all evidence *first*, then freeze; re-issue `frozen` after any capture on a paused job and record `pause_leaked_ms`; document that `pause` stops **brow**, not the page and not the server (session timeouts, rate limits and OTP validity keep ticking — a 40-minute pause can invalidate a login). Video cannot be paused, only segmented: close the segment, start a new one on resume, concat at job end, and record the wall-clock gap explicitly.
**Confidence:** confirmed · `70-` §5.3

### ADR-22 — Storage: SQLite (rusqlite 0.40.1, `bundled`, WAL) for jobs/site-graph/approvals; append-only JSONL (+zstd segments) for events; content-addressed blake3 blob store for artifacts

**Why:** the site graph is genuinely relational (edges → nodes → evidence → requests; "routes `declared` with no `observed` edge" is a join). SQLite is WAL-crash-safe, allows a **second reader process**, and is inspectable with `sqlite3` when the daemon is wedged. redb 4.1.0 and fjall 3.1.8 are better k/v stores but are **single-process by design** (redb maintainer, issue #838: *"You'll need to wrap it in an IPC layer"*) and their files are opaque. `sled` is dead (`1.0.0-alpha.124`, 2024-10-11). State transitions write the `jobs` row and the `job_events` row **in one transaction** so on-disk state and the event log can never disagree; a `daemon_boot_id` column makes crash recovery a single idempotent `UPDATE` to `interrupted`.
**The `bundled` objection is smaller than believed:** measured on a pristine crate, clean debug build **2.97 s total** (libsqlite3-sys unit 1.48 s), clean release 13.61 s total — not the 15–25 s *increment* the corpus first claimed. The C-toolchain requirement is the only surviving objection (absent on bare `rust:alpine`).
**Events as JSONL** because `tail -f` works, a torn last line is trivially recoverable, and it costs nothing; roll segments at 16 MB / 60 s with a sidecar index (`first_seq`, `mono_us` range, kind counts, url bloom) so `--since`/`--filter` skip whole segments. **The log cannot be both crash-perfect and fast**: fsync-per-line caps at ~100–1000 writes/s, which a chatty page exceeds. Batch fsync every ~50 ms and **document the window** rather than implying durability.
**Refs are never persisted** — they are invalid the moment the page navigates, which is exactly the property the spec demands.
**Confidence:** likely · `20-` §6, `70-` §5.2, `90-` §5.2

### ADR-23 — IPC stays newline-JSON over a `0600` unix socket in a `0700` dir, with a v2 envelope (`id` / `ev` / `end` / `cancel`); **not** JSON-RPC 2.0; single-instance via `flock`, not bind-as-lock

**Why (not JSON-RPC):** JSON-RPC has no server-push stream correlated to a request id — this is exactly why LSP had to bolt on `$/progress` and `$/cancelRequest`. Decisively: JSON-RPC's `method: String` would **reopen the raw-CDP hole** that a closed `Request` enum closes at the type level; the repo already has a test guarding it (`no_request_variant_can_carry_a_cdp_method`). Borrow JSON-RPC's *error* discipline (stable string `code` + human `message` + actionable `hint`) and nothing else. Cancelled requests must still produce an `end` frame with `code:"cancelled"` — never leave an id hanging.
**Why (flock):** the current `exists → connect → unlink → bind` sequence is **demonstrably racy** — after `unlink()` a second `bind()` **succeeds while the first listener is still open and accepting**, so new clients reach the second daemon while the first stays alive, holding browsers, and unreachable. `flock(LOCK_EX|LOCK_NB)` on `run/browd.lock` gave correct `EAGAIN(35)` exclusion on macOS and is released automatically on `SIGKILL`. Acquire the lock **before** unlinking anything.
**`--follow` is daemon push, not file tailing:** push delivers the terminal frame, survives log rotation (kqueue watches an inode), carries high-frequency progress that never hits disk, and gives real backpressure with an explicit `dropped` count. Bounded channels everywhere on any path fed by the browser — the repo's current `unbounded_channel` in `cdp/transport.rs` and `cdp/conn.rs` is a latent OOM on a page firing `Network.*` at kHz.
**Say plainly in the README: the security boundary is the uid, not brow.** Any process running as the user can `connect()` and drive a browser holding real sessions. That is strictly more power than reading `~/.ssh`. Socket permissions are not sandboxing.
**Confidence:** likely (envelope) / confirmed (the race, the flock fix, the uid limit) · `70-` §2–3, `20-` §4

### ADR-24 — Process plumbing: `command_fds` 0.3.3 + `tokio::process::Command` + `tokio::net::unix::pipe::{Sender,Receiver}::from_owned_fd`; 4 crates, not 14

**Why:** verified end-to-end against Chrome 151 (`SPAWNED chrome pid=… / SENT Browser.getVersion / RECV {"product":"Chrome/151.0.7922.72"}`). It removes 3 `unsafe` blocks and the fd-leak-on-spawn-failure path, handles the fd-collision case the hand-rolled code does not, and `FdMapping.parent_fd` is an `OwnedFd` so the parent's copies close on spawn. It replaces 2 blocking threads per browser. Import must be `command_fds::{CommandFdExt, FdMapping}` — `command_fds::tokio::CommandFdExt` is a private re-export and a compile error.
**Why 4 crates:** splitting a workspace does **not** reduce clean build time; it helps incremental builds only along a real dependency cut. `inspection`, `input`, `capture`, `crawler`, `events` would all depend on `cdp-protocol` + `cdp-transport` + `sessions`, so any session-model change rebuilds everything anyway. 14 crates for ~7 K lines is ~530 lines/crate. **The one split that pays is isolating the ~2 MB generated `cdp.rs`.** Recommended: `brow-cdp` (generated types + transport + session mux + launch) · `brow-core` (tree, input, capture, events, crawler, jobs, policy, artifacts, storage) · `brow` (bin) · `browd` (bin) · `xtask` (not in default members, keeps codegen deps out of the graph). Split further only when `cargo build --timings` says so.
**Honest counterpoint the owner should weigh:** a separate `policy` crate that *structurally cannot import CDP types* is a real security boundary that the 4-crate layout gives up. That is a values call, not a compile-time one.
**Enforce the ban mechanically:** `cargo deny` `[bans]` on `chromiumoxide`, `headless_chrome`, `thirtyfour`, `fantoccini`, `chromey`, plus `playwright|puppeteer|selenium` patterns. It is the only way "no Playwright anywhere in the dependency graph" stays true after 20 dependency bumps. Pair with `cargo-audit`, `--locked`, and pinned protocol SHA-256s.
**Confidence:** confirmed (plumbing) / likely (crate count) · `20-` §3, §10

### ADR-25 — Protocol drift is managed, not hoped away — and schema diffs are not enough

**Why:** **38 of 57 domains in Chrome 151 are `experimental: true`**, including `CSS`, `DOMSnapshot`, `Accessibility`, `Storage`, `CacheStorage`, `ServiceWorker`, `Preload`, `PerformanceTimeline`, `Overlay`, `LayerTree`, `Memory`, `SystemInfo` — essentially the whole load-bearing surface. `experimental=false` codegen is **not an option**. Member-level flags matter too: `DOM.getContentQuads`, `DOM.getFrameOwner`, `Input.insertText`, all three `synthesize*`, `Runtime.evaluate.throwOnSideEffect` and `.timeout` (but **not** `returnByValue`, which is stable), `Network.streamResourceContent`, `Network.dataReceived.data`, all `*ExtraInfo` events, `Page.frameStartedNavigating`, `Page.setWebLifecycleState`, `Emulation.setLocaleOverride` (but not `setTimezoneOverride`/`setDeviceMetricsOverride`), all four `Target.createBrowserContext` params. `Browser.grantPermissions` is experimental **and deprecated** — use `setPermission`, whose descriptor names are **web-platform names** (12 confirmed accepted; legacy `PermissionType` values like `videoCapture` rejected `-32602`).
**Policy:** vendor + codegen + milestone gate + lazy `-32601` discovery + a fixture test per experimental call that fails loudly + `xtask check-protocol` diffing against upstream head + record `Browser` and `Protocol-Version` in every artifact + a CI leg against `chrome-beta` with `continue-on-error` as an early warning.
**The gap a schema diff does not close, and it is the class that actually bit here:** the 16384 wrap, the tab/page filter rejection, the bfcache flush, the visibility semantics, the freeze-cancelled-by-screenshot — **none of these are visible in `/json/protocol`.** The project needs a small **behavioural conformance suite** (10–20 fixtures) run against every Chrome the daemon sees for the first time, not just a schema diff. Chrome also auto-updates silently, including *while a browser instance is running* — detect binary mtime/version change at relaunch and refuse to reuse a negotiated capability set.
**Confidence:** confirmed (the surface) / **open** (the auto-update story) · `20-` §2, `90-` §10.15, `10-` §9.4

### ADR-26 — No evasion, and say so

**Why:** full 9-row measured matrix: no-CDP control `false`; fixed non-zero port `false`; port + `--enable-automation` `true`; **`--remote-debugging-port=0` `true`**; **pipe headless `true`; pipe headful `true`**; pipe + `--enable-automation` `true` (unchanged); pipe + `--disable-blink-features=AutomationControlled` `false`. Mechanism found in `content/child/runtime_features.cc`. Do not pass `--enable-automation` (it now only changes the infobar and password-save UI — cosmetic, since the pipe already sets the fingerprint) and do not pass the evasion flag. Never `--no-sandbox`, `--single-process`, `--disable-web-security`, or `--disable-features=IsolateOrigins,site-per-process` — killing site isolation would remove OOPIF targets *and* the main renderer mitigation on a machine browsing arbitrary sites for an agent.
Frame the whole detection section as *"why your app behaves differently under automation"*, with the measured signal table, **not** as a bypass toolkit. Synthesised input is irreducibly distinguishable: straight paths, no micro-tremor, uniform inter-keystroke intervals, no typo-and-correct, sub-millisecond dwell, formula-matched fling velocities. Optional humanisation (`PathStyle::Human`) is an **ergonomics** feature for hover/gesture UIs and must be documented as such.
**Confidence:** confirmed · `10-` §6.4, `40-` §11

### ADR-27 — Packaging: one `skills/browser/SKILL.md` conforming to agentskills.io + **two** symlinks; no MCP server in v1

**Why:** `SKILL.md` is a genuine cross-vendor open standard in 2026 (Anthropic-originated, ~46 clients including Claude Code, Codex, Cursor, OpenCode, Gemini CLI, Copilot, VS Code, Goose, Amp). **The install matrix is two symlinks, not four**: `~/.claude/skills/browser` covers Claude Code + Cursor (legacy path) + OpenCode (global path), and `~/.agents/skills/browser` covers Codex + Cursor + OpenCode. *(Corrected: `~/.opencode/skills/` is **not** a path OpenCode reads — the drafted installer would have been a silent no-op, the worst class of install bug because it presents as "the model just never uses the skill".)* Symlink, don't copy, so a `brow` upgrade updates every harness at once. Frontmatter stays in the standard's intersection: `name`, `description`. Claude Code truncates `description` + `when_to_use` at **1,536 characters**; Codex caps the *listing* at 2 % of the context window (or 8,000 chars when unknown) and shortens descriptions first.
**Rejected:** MCP-first. A CLI costs ~0 protocol-framing tokens per call; `chrome-devtools-mcp` needs `--experimentalPageIdRouting` just to let two agents share one server. **But do not cite gstack's "30–40 K tokens of MCP framing vs zero" number in brow's own README** — it is the vendor's own marketing, "zero" is definitionally false (brow's stdout is tokens too), and a fat-tree CLI can lose to a lean MCP tool on total tokens. If CLI-over-MCP needs defending, measure it end-to-end and publish both.
**CLI contract for an LLM consumer:** `--json` universal with field projection; hard output budget with a *machine-readable* truncation marker (`… [truncated 812 of 1204 nodes; re-run with --scope @e17]`); pagination on every list with `page 2/7 · 300 of 2041 items`; refs generation-scoped with the generation in the snapshot header; errors are `{code, message, next}` where `next` is a literal runnable command; reserved exit codes `0` ok, `2` usage, `3` daemon-not-running/precondition, `4` capability-denied, `5` waiting-for-approval, `6` stale-ref, `7`/`124` timeout; `browserctl help --json` emits the full command tree so the skill can teach itself; `browserctl <cmd> --explain` prints the exact CDP sequence (auditability, and it makes the no-raw-CDP policy inspectable); screenshots go to files, paths to stdout; logs to stderr, always.
**Confidence:** confirmed · `95-` §C1–C3

## 4. The unsettled fork — who runs the LLM loop in a detached job?

This is the one decision the owner must make **before any code is written**, because it determines whether `crates/jobs` contains a decision queue, whether `browserd` ever needs a model client, and what `SKILL.md` actually instructs the agent to do.

### The problem, stated precisely

The spec promises `browserctl job start --detached --record-video` plus `status` / `logs --follow` / `artifacts` / `pause` / `resume` / `stop`, and dangerous actions that park the job in `waiting_for_approval`. The crawler research then says the agent is where the judgement lives — *"hand the residual to the agent as a compact list (≤40 items) and let it choose/rank… this is where the LLM earns its keep"* (`90-` §4.2 step 6). Both are reasonable. Together they are contradictory:

- A 2,000-action crawl **cannot** round-trip to an LLM per action (latency, token cost, and the calling agent's turn has already exited).
- A job that parks on `waiting_for_approval` has, by construction, **no TTY to park to** — the originating terminal is gone.
- The daemon calling a model itself would violate "no cloud APIs, no telemetry" unless the model is local, which is a whole other product — and it would make `browserd` a credential holder, the single worst place to put one given that the socket's boundary is the uid.
- **MCP sampling — the one standardised way for a server to borrow the host's LLM — is deprecated** as of MCP revision `2026-07-28` (SEP-2577): *"New implementations SHOULD NOT adopt it."* Nuance the corpus initially missed: it remains in the spec for **at least twelve months** (so ≥ 2027-07-28), and it was **reshaped, not merely deprecated** — `createMessage` is now delivered inside `InputRequiredResult.inputRequests` and returned via `inputResponses` on a retried call, and it gained `tools`/`toolChoice` behind a `sampling.tools` capability. So the argument is not "the door is closing" but "**the door moved**": code written against the older shape would already be wrong.

### The options

| | Model | Who decides | Pros | Cons |
|---|---|---|---|---|
| **A** | **Fully autonomous daemon (heuristics).** The agent supplies a config up front (priorities, veto lexemes, form fixtures, budget); the job runs a deterministic policy-driven loop and the agent reads the report afterwards | `crates/crawler` heuristics | No LLM dependency; honours every constraint; detached jobs are genuinely detached | Loses exactly the semantic judgement the crawler research says is the differentiator. Icon-only destructive buttons and "which of 30 links matters" get keyword rules — and **2–45 % of clickables have no accessible name at all** |
| **B** | **Daemon calls a model.** `browserd` holds an API key or a local model | daemon | Best action selection; true autonomy | Violates "no cloud APIs / no telemetry" as written; a local model is a second product (Ollama/llama.cpp is a large unstated dependency); key management in a uid-boundary daemon is a security regression |
| **C** | **Agent-side supervision, async.** The job runs autonomously but emits a bounded `needs_decision` queue; the agent answers via `brow job answer <job> <q-id>` on its next turn (or a `claude -p` / `--bg` session); the job keeps working other frontier branches meanwhile | agent, asynchronously | Keeps the LLM where it earns its keep; daemon stays model-free, deterministic and testable; detached jobs still make progress; maps onto how Claude Code / Codex actually run (turn-based, resumable) | Needs a queue, correlation ids, TTLs and a "nobody ever answers" policy; the agent must be *told* to check back — a `SKILL.md` problem, not a daemon problem |
| **D** | **Plan-then-replay.** The agent produces a full action plan interactively; the detached job is a deterministic replay | agent, up front | Simplest; perfectly auditable; excellent for regression runs | Useless for exploration — a crawl's whole point is that you do not know the plan; and replay divergence on authenticated CRUD is **unmeasured** (see R7) |

### Recommendation: **C, built as A plus gates, with D as a separate later feature**

1. **The daemon never calls a model.** That constraint stays absolute and is the reason brow is worth building. It is also what makes plans diffable, replayable against fixtures, and honest as a provenance record — `edge.status ∈ {declared, observed, discovered, inferred, blocked}` maps cleanly onto "the plan declared it" / "the executor observed it" / "a gate answer inferred it".
2. **Every detached job is defined by a `JobPlan`** submitted at `job start`: capability set (intersected with the caller's grant, never widened), origin allowlist, budget, priorities, veto lexemes, form fixtures, and a `decision_policy` of `auto | ask | stop`. Everything the daemon can do is a **closed enum of ops** — the same structural guarantee as the IPC `Request` enum.
3. **The job always makes progress under heuristics** (option A behaviour) and never blocks on the agent for ordinary action selection. A job whose agent never comes back still produces a coverage report.
4. **Two queues, not one, and they must not be conflated:**
   - `needs_decision` — semantic questions (which of these 30 affordances; is "Retire this workspace" destructive; is this state genuinely new). Answerable by the **agent**. TTL-bounded; on expiry `decision_policy` decides (`auto` → heuristic, `ask` → skip and record `blocked{reason:"undecided"}`, `stop` → park).
   - `waiting_for_approval` — irreversible actions per the spec (publish, delete, purchase, send, OTP, upload, permission grant, cookie import). Answerable by a **human only**, bound to ref + document generation, expiring (30 min default), re-verified by screenshot diff before execution. Delivery: the pushed `{"ev":"approval"}` frame on any `--follow` stream, exit code **5**, a desktop notification (verified: `osascript` exits 0 even from a TTY-less `ProcessType=Background` LaunchAgent — though exit 0 does not prove a banner was *seen*, and Focus/DND is untested), and a user-configurable `on_approval` hook for Slack/tmux/Claude Code hooks.
5. **`brow job answer` and `brow approve` are different verbs with different auth.** `approve` is refused unless stdin is a TTY or a signed token is presented; `answer` is the agent's channel.
6. **D ships later as `job replay <plan.json>`** — genuinely valuable for regression runs and nearly free once the action log exists.

**What this buys:** a deterministic, testable, model-free daemon; the agent's judgement used where it changes outcomes and nowhere else; detached jobs usable without a live terminal; and a concrete answer to "who is the human".
**What it costs:** a decision queue with TTLs and correlation ids in `crates/jobs` (~1.5 engineer-weeks), and a `SKILL.md` that must teach the agent to check back — the part most likely to be got wrong, and which should be prototyped against a real Claude Code / Codex session **before the protocol is frozen**.
**What is unmeasured and should be spiked:** how often a plan actually hits an undecidable point. Run 5–10 real sites and count. That number decides whether "detached job" is a feature or a euphemism.

### The "no Playwright" cost list

These are the papercuts Playwright/Puppeteer absorb that brow now owns. None is hard individually; together they are most of the schedule, and each is a *silent-wrongness* bug rather than a crash.

1. **Actionability + retry semantics** — visible / stable / receives-events / enabled / editable, per action class (ADR-15). Note `opacity:0` **passes** visible.
2. **Auto-waiting and navigation lifecycle** — `Page.lifecycleEvent` plumbing, `networkAlmostIdle`, settle windows, the `WaitForHelper` state machine and its four constants.
3. **The US keymap table** — `code` + `key` + `windowsVirtualKeyCode` + `text`, ~253 rows, code-generated from Chromium (ADR-14).
4. **OOPIF session stitching and cross-frame coordinate composition**, including the corrected affine guard — and the *frame lifecycle bookkeeping* that is the genuinely hard part.
5. **Browser discovery** across macOS/Linux/Windows with priority weights (and never launching from `/Volumes` — chrome-launcher assigns it a negative weight because it is a mounted DMG).
6. **The launch flag set** — which of ~40 flags are current, which were removed in 2016–2019, which are actively harmful.
7. **Protocol version skew** — pinning, codegen, milestone gating, lazy capability discovery, behavioural conformance.
8. **Locator / re-binding engine** — the stability-ranked chain (`data-testid` → non-generated `id` → role+name+nth → container+text → CSS → XPath), recorded per edge, with a *drop to a weaker link* reported as a signal.
9. **Dialog handling** — dialogs **pause the renderer**; you must *always* answer `beforeunload` because `Page.navigate` blocks on it, and its message is deliberately empty (custom text has been ignored since 2016).
10. **Downloads** (`Browser.setDownloadBehavior`, per `browserContextId`) and **file chooser interception** (`Page.setInterceptFileChooserDialog`, incl. `cancel:true` so a stray chooser cannot wedge a page).
11. **Three drag strategies**, probed rather than guessed — HTML5 DnD and pointer DnD (dnd-kit, react-beautiful-dnd) are mutually exclusive mechanisms and `dispatchDragEvent` does nothing for the latter.
12. **Screenshot mechanics** — scroll normalisation, coordinate spaces, clipping ancestors, occlusion sampling, the 16384 cap, DPR pinning.
13. **The entire video pipeline** — screencast acking, frame indexing, concat manifests, `-fps_mode passthrough`, even-dimension filtering, clock normalisation.
14. **Network plumbing** — the `*ExtraInfo` join and its ordering hazard, multi-`Set-Cookie` `\n`-joining, body-capture policy, HAR `buildTimings` (including DevTools' deliberate quirks), redaction at ingest.
15. **Known-bug workarounds** — the `setEmitTouchEventsForMouse` ban + input-dead latch, `preventFling` defaulting to true, `sessionId` not being a frame number, `queryAXTree` exact-match, `getContentQuads` returning the iframe border box, the hidden-tab rAF hang.
16. **Process lifecycle** — orphan detection with start-time verification, `kill(-pgid)` not `kill(pid)`, zombie-vs-alive (`kill(pid,0)` succeeds on zombies), profile lock artifacts, crash/sad-tab recovery.
17. **A fixture corpus** for every one of the above.

### Blunt assessments

- **Framework adapters are not one feature, they are two.** *Detection* (name + version) is trivial and works everywhere — even from an isolated world, since `ng-version` and `data-svelte-h` are DOM attributes. *Introspection* is a production-build casualty across the board and *route extraction* is: solved for Vue/Nuxt (293 routes) and SvelteKit (statically, HTTP-only, including hidden `(admin)` groups), partial by design for React Router (lazy fog-of-war, a **lower bound**, and its manifest entries are route *definitions* with splats — never a coverage denominator), and **verified impossible at runtime** for Next.js App Router and production Angular. Budget: "React + Vue: 1 week; Flutter: 0.5 weeks; everything else: detection only, plus an optional repo-aware mode reading `.next/routes-manifest.json` / `.svelte-kit/` — which is a filesystem-scope *policy* question, not an engineering one."
- **Flutter is a real feature and cheaper than it looks.** Source-derived from `semantics_helper.dart`: the desktop enabler activates on `keyup`/`keydown` as well as clicks, so **`DOM.focus` + `Input.dispatchKeyEvent` enables semantics with no DOM mutation at all** (prefer it; keep the verified reposition-then-click as fallback). But there is an unbudgeted hazard that is **not** a Flutter-adapter detail: the *mobile* enabler's placeholder covers the **entire viewport** and consumes events for **300 ms**, so brow's own `Emulation.setDeviceMetricsOverride` can cause an invisible full-viewport element to swallow the agent's first gesture on any Flutter page, whether or not the adapter was requested.
- **Cascade-winner fidelity is a research project.** CDP hands you all matches, specificity (including the experimental per-simple-selector `components` breakdown), layer order integers and source ranges — but never the winner. `!important` × cascade layers × `@scope` × shadow tree order is a week of careful work *plus* a fixture corpus, and you will still be wrong in corners. v1 answer: matched rules ordered by specificity, no winner claim.
- **The crawler's schedule risk is not the code, it is R7 and R8.** Fix the frame-blindness *before* measuring replay divergence, or the measurement is uninterpretable. If divergence is high, the honest product is "crawl the `restorable_by_url` states thoroughly and report the rest as `blocked{reason:"not-restorable"}`" — a smaller and still-valuable feature.
- **Total, honestly: ~56 engineer-weeks** for the spec as written (≈ 26 + 14 + 16), excluding open-ended signature tuning and excluding whatever R7 forces. Roughly 13 months for one person, two quarters for two. The MVP alone is ~6 months.
- **You are not inventing the category.** `gsd-browser` (`gsd-build/gsd-browser`, 252★, Rust + `chromiumoxide` + persistent daemon + `@v1:e1` refs + **92** commands + `--json` everywhere, MIT/Apache-2.0) and `gstack browse` (daemon, `@e<N>`/`@c<N>` refs, deny-default CDP allowlist, three token tiers) already occupy it. Differentiate explicitly on: the **unix socket + pipe transport** (gsd-browser uses loopback TCP 9333 — reachable by every local process), the **fat tree** including closed shadow roots (invisible to every JS-injected snapshotter, and gstack is built on Playwright's `ariaSnapshot()`), **real-input fidelity**, **video/action-log sync**, and the **state-aware site graph with edge provenance and route coverage**. Decide the source-provenance policy before anyone reads gsd-browser's code.

## 9. How to read the corpus

Four conventions matter:

1. **Every dossier ends with one or two "Verification pass" tables.** Where the body and a verification table disagree, **the verification table wins.** The bodies carry inline `> Corrected 2026-08-04` / `> REFUTED` blocks, but a skim will miss them. Where two dossiers disagree (this happened twice — fd-3 EOF behaviour, and `navigator.webdriver`), the verification tables reconcile them and this README carries the reconciled version.
2. **Confidence tags are load-bearing.** `confirmed` means measured or read from primary source. `likely` means secondary sources agree. `UNVERIFIED` means reasoning — and the corpus is honest about how much of the supervisor design, all of Windows, and all of Linux falls in that bucket.
3. **The "Limits and impossibilities" section of each dossier is the most valuable part.** It is what stops brow from promising things CDP cannot do — the difference between a tool an agent can trust and one it silently gets wrong answers from.
4. **Numbers are bytes, not tokens, wherever it matters.** The byte and node counts replicate across independent runs to within 0.1 %; the bytes→tokens constant was never validated with a tokenizer. Gate policy on bytes.
